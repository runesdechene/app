# L'énergie revient — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** découvrir reste gratuit à moins de 100 km de sa position ; au-delà, l'énergie se paie (1/2/3 points), avec une jauge de 10 points + 1 par Fragment, un point par heure, réglable dans le Hub.

**Architecture:** la base calcule tout (prix, jauge, recharge) : une migration 399 ajoute les réglages, un calcul unique du maximum partagé V1/V2, `mon_energie`, `cout_decouverte`, et fait payer `decouvrir_lieu`. La V2 lit ces fonctions : une zone `features/energie` (la jauge sur la carte, posée par la coquille) et la zone `features/lieu` (le prix sur le voile). Le Hub gagne une page « Énergie » ; « Réglages » perd sa partie énergie.

**Tech Stack:** PostgreSQL (Supabase), React 19 + TanStack Query + CSS modules (V2), React 18 (Hub), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-01-v2-energie-design.md` · Maquettes Figma 358:164, 358:222, 358:231, 358:241.

## Global Constraints

- Gratuit à moins de `decouverte_gratuite_km` (100) ; 1 point jusqu'à `decouverte_palier_1_km` (500) ; 2 points jusqu'à `decouverte_palier_2_km` (1 500) ; 3 points au-delà ; 3 points sans position.
- Jauge = `default_max_energy` (passe à 10) + 1 par Fragment possédé ; un point toutes les `energy_base_cycle` secondes (3 600). Aucun bonus de Compagnie, de Fragment spécial ni d'outsider sur l'énergie.
- Une découverte déjà faite (ou un lieu ajouté / visité par soi) ne se paie jamais.
- Le serveur a toujours le dernier mot sur le prix ; l'écran n'invente jamais un chiffre.
- Migrations : en-tête `-- WHY:` + `SCHEMA CHECKED`, tout `CREATE OR REPLACE` copié de la définition **live** ; testées dans `BEGIN … RAISE EXCEPTION 'BILAN' … ROLLBACK` ; appliquées par Uriel (`pnpm dlx supabase db push --linked`), puis `pnpm --filter web-v2 gen:types`.
- V2 : chef-d'œuvre de simplicité ; pas de `any` ; jetons CSS seulement (tailles, interlignes, espacements de lettres) ; une zone n'importe pas une autre zone ; en-tête `QUOI / POURQUOI` sur chaque fichier ; tout est animé, `prefers-reduced-motion` respecté.
- Tutoiement dans la V2. « Découvrir » = à distance ; « visiter » = sur place.

## Review Focus

1. Un joueur dont la jauge stockée dépasse le nouveau maximum (ancien bonus de Compagnie) : on ne lui retire rien ; la jauge affiche ses points et ne se recharge plus tant qu'il est au-dessus.
2. Deux découvertes payantes lancées presque en même temps (double toucher, V1 + V2) : la seconde ne doit jamais faire passer la jauge sous zéro — verrou `FOR UPDATE`.
3. Le prix affiché devient faux entre l'ouverture du voile et le geste (dépense dans l'autre app) : le serveur refuse, le voile passe en « pas assez d'énergie » avec les chiffres relus.
4. La position arrive après l'ouverture du voile, ou jamais : le prix passe de « … » au vrai prix, ou reste au prix sans position, sans bloquer le geste quand la jauge suffit.
5. Un réglage saisi de travers dans le Hub (vide, négatif, paliers dans le désordre) : la page refuse d'enregistrer et dit pourquoi.

Chaque ligne a son test dans la tâche qui possède le code (Task 1 : 1 et 2 ; Task 4 : 3 et 4 ; Task 5 : 5).

```sql
--      premier retour des testeurs). Découvrir reste gratuit à moins de 100 km de sa position ;
--      au-delà 1 / 2 / 3 points. Jauge : 10 + 1 par Fragment, un point par heure ; elle remplace
--      tous les bonus d'énergie (Compagnie, Fragments spéciaux, outsider). La jauge est partagée :
--      get_user_energy (V1) prend le même maximum et la même recharge.
-- SCHEMA CHECKED (01/10/2026, …) : <colonnes et définitions lues au Step 1>

INSERT INTO app_settings (key, value) VALUES
  ('decouverte_gratuite_km', '100'), ('decouverte_palier_1_km', '500'),
  ('decouverte_palier_2_km', '1500'), ('decouverte_cout_1', '1'),
  ('decouverte_cout_2', '2'), ('decouverte_cout_3', '3')
ON CONFLICT (key) DO NOTHING;
UPDATE app_settings SET value = '10' WHERE key = 'default_max_energy';

CREATE OR REPLACE FUNCTION public._reglage(p_cle text, p_defaut numeric)
 RETURNS numeric LANGUAGE sql STABLE SET search_path TO 'public'
AS $$ SELECT COALESCE((SELECT value::numeric FROM app_settings WHERE key = p_cle), p_defaut) $$;

-- Le maximum de la jauge : un seul calcul, pour la V1 et la V2.
CREATE OR REPLACE FUNCTION public._energie_max(p_user text)
 RETURNS int LANGUAGE sql STABLE SECURITY DEFINER SET search_path TO 'public'
AS $$
  SELECT public._reglage('default_max_energy', 10)::int
       + (SELECT count(DISTINCT fragment_id)::int FROM user_fragments WHERE user_id = p_user)
$$;

-- Le prix d'une découverte depuis une position (null : pas de position, prix le plus haut).
CREATE OR REPLACE FUNCTION public._cout_decouverte(p_id text, p_lat numeric, p_lng numeric)
 RETURNS json LANGUAGE sql STABLE SET search_path TO 'public'
AS $$
  WITH d AS (
    SELECT CASE WHEN p_lat IS NULL OR p_lng IS NULL THEN NULL
                ELSE public.haversine_km(p_lat, p_lng, l.latitude, l.longitude) END AS km
    FROM places l WHERE l.id = p_id)
  SELECT json_build_object(
    'distanceKm', round(d.km, 0),
    'cout', CASE
      WHEN d.km IS NULL THEN public._reglage('decouverte_cout_3', 3)
      WHEN d.km < public._reglage('decouverte_gratuite_km', 100) THEN 0
      WHEN d.km < public._reglage('decouverte_palier_1_km', 500) THEN public._reglage('decouverte_cout_1', 1)
      WHEN d.km < public._reglage('decouverte_palier_2_km', 1500) THEN public._reglage('decouverte_cout_2', 2)
      ELSE public._reglage('decouverte_cout_3', 3) END::int)
  FROM d
$$;
REVOKE ALL ON FUNCTION public._reglage(text, numeric), public._energie_max(text),
  public._cout_decouverte(text, numeric, numeric) FROM PUBLIC, anon, authenticated;
```

```sql
CREATE OR REPLACE FUNCTION public.mon_energie()
 RETURNS json LANGUAGE plpgsql SECURITY DEFINER SET search_path TO 'public'
AS $$
DECLARE v json;
BEGIN
  IF auth.uid() IS NULL THEN RAISE EXCEPTION 'Connexion requise' USING ERRCODE = '42501'; END IF;

 RETURNS json LANGUAGE plpgsql SECURITY DEFINER SET search_path TO 'public'
AS $$
DECLARE c json; e json;
BEGIN
  IF auth.uid() IS NULL THEN RAISE EXCEPTION 'Connexion requise' USING ERRCODE = '42501'; END IF;
  IF NOT public._lieu_visible(p_id) THEN RAISE EXCEPTION 'Lieu introuvable' USING ERRCODE = 'P0002'; END IF;

  e := public.mon_energie();
  RETURN json_build_object('cout', (c->>'cout')::int, 'distanceKm', (c->>'distanceKm')::numeric,
    'points', (e->>'points')::int, 'max', (e->>'max')::int, 'prochainDans', (e->>'prochainDans')::int,
    'parPoint', (e->>'parPoint')::int);
END $$;
```

```ts
/**
 * QUOI     — une attente lisible : « 23 min », « 1 h », « 1 h 24 ».
 * POURQUOI — la jauge et le voile disent quand revient le prochain point d'énergie.
 */
export function attente(secondes: number): string {
  const minutes = Math.max(1, Math.ceil(secondes / 60))
  if (minutes < 60) return `${String(minutes)} min`
  const heures = Math.floor(minutes / 60)
  const reste = minutes % 60
  return reste === 0 ? `${String(heures)} h` : `${String(heures)} h ${String(reste).padStart(2, '0')}`
}
```

```ts
// Demande la position, quitte à faire apparaître la question du navigateur : seulement sur un
// geste de l'Explorateur (« Utiliser ma position »).
export function demanderPosition(): Promise<Point | null> {
  if (!('geolocation' in navigator)) return Promise.resolve(null)
  return new Promise((resolve) => {
    navigator.geolocation.getCurrentPosition(
      (p) => { resolve({ latitude: p.coords.latitude, longitude: p.coords.longitude }) },
      () => { resolve(null) },
      { maximumAge: 10 * 60 * 1000, timeout: 8000 },
    )
  })
}
```
