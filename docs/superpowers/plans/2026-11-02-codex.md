# Le Codex V1 — plan de mise en œuvre

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** livrer le Codex (onglet, page, fiches, anecdotes, découverte animée, contenu saisi au Hub
et écrit dans Shopify, fiche produit de la boutique) pour le jeudi 05/11.

**Architecture:** le contenu public d'un motif vient de Shopify par la synchro existante
(`synchroniser_fragments` → `title_fragments`) ; l'état personnel (porté, scans, numéro, anecdotes
trouvées) vit en base et sort par deux RPC (`mon_codex`, `mon_fragment`) ; l'appli assemble les deux.
Une seule carte de Fragment (celle du profil) sert au profil et au Codex.

**Tech Stack:** React 19 + TS strict + TanStack Query + CSS modules (`apps/web-v2`), Hub React +
Netlify functions (`apps/hub-v2`), Postgres/Supabase (`supabase/migrations`), Liquid (thème voisin
`../shopify (Runes de Chêne)`), vitest.

**Spec:** `docs/superpowers/specs/2026-11-02-codex-design.md` — maquettes Figma `MKqyVhDPreg06PMEAaDxde`
(« Codex V1 — F / C / D / G », « Scan — un nouveau Fragment sort de l'ombre », composants
« Codex V1 / Fragment » et « Codex V1 / Rareté »).

## Global Constraints

- Quatre livraisons, chacune en ligne et utilisable seule, dans cet ordre : **(1)** Tasks 1-8,
  **(2)** Tasks 9-12, **(3)** Task 13, **(4)** Tasks 14-15. Déploiement selon
  `.claude/rules/deploiement.md` (lu avant), `pnpm deploy:app` / `pnpm deploy:hub`, jamais d'auto-deploy.
- Migrations : `NNN_` à partir de **577** ; en tête `-- WHY :` et `-- SCHEMA CHECKED` ; tout
  `CREATE OR REPLACE` part de la définition **live** (`pg_get_functiondef`) copiée entière ;
  `node scripts/migration-preview.mjs <fichier>` ; `npx supabase db push --dry-run --linked` puis
  `--linked` ; vérification en prod ; `python3 scripts/graphify-sql.py`. Un nom de colonne se lit
  dans `information_schema`, jamais deviné.
- TS strict : pas de `any`, `@ts-ignore`, `as unknown as`. Pas de `console.log`. En-tête
  `QUOI / POURQUOI` sur chaque fichier, `README.md` par dossier, > 700 lignes → découper.
- **Jamais d'italique** ; IM Fell English en romain. Bouton clair : fond parchemin, contour
  `#C9BAAC` 1 px, ombre `0 3px 8px -1px rgba(89,64,31,.22)` (`.claude/rules/interface.md`).
- Toute transition passe par les jetons (`--duree-douce`, `--courbe-douce`, `--duree-elan`,
  `--courbe-elan`) ; `prefers-reduced-motion` respecté ; toute `<img>` distante par `aLaTaille`.
- Un écran n'est fini que comparé à sa maquette à 390 px (et à 1440 px pour le panneau PC).
- Les mots de l'interface : « Porteur », « Fragment », « Codex », « anecdote » ; le compte d'une
  découverte se dit dans sa collection (« 2 sur 5 de La Garde d'Acier »), jamais sur le total.
- Rang du numéro de Porteur : **1-10 rare, 11-50 peu commune, 51+ commune**. Tirage d'une anecdote :
  **commune 60 %, peu commune 30 %, rare 10 %**. « Creuser encore » : **2 énergies**. « Nouveau » :
  `title_fragments.created_at` de moins de **60 jours**.

## Review Focus

1. **Un Fragment masqué (`visible = false`)** n'apparaît nulle part dans le Codex et ne compte dans
   aucun total ni aucune collection — test dans Task 2 (`mon_codex`) et Task 6 (parser).
2. **Un Fragment sans collection (`heritage` nul)** se range dans une section « Hors collection »,
   sans titre à gagner — test Task 6.
3. **Un compte sans aucun scan ni Fragment** voit toutes les collections repliées et la phrase
   « Scanne ton premier Fragment » au lieu d'une page vide — test Task 6.
4. **Deux « Creuser encore » rapprochés, ou 1 énergie restante** : la base verrouille la ligne
   (`FOR UPDATE`), refuse sous 2 (`RDC01`), ne débite jamais deux fois — vérification SQL Task 9,
   message « Plus assez d'énergie » testé Task 11.
5. **Deux Fragments reliés en même temps au même motif** ne reçoivent jamais le même numéro
   (unicité `(fragment_id, numero)` + verrou) — vérification SQL Task 1.
