# Hub V2 — plan 3 : Le jeu

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** les sept écrans du domaine « Le jeu » du Hub V2 — Énigmes, Énigmes signalées, Cultures, Natures, Titres, Bannières, Énergie — au design des plans 1 et 2, à la place des écrans « bientôt ».

**Architecture:** une zone `apps/hub-v2/src/features/jeu/` (api, hooks, lib, components), sur les briques des plans 1-2 (EnTeteDePage, Tiroir, ChampDeRecherche, Pages, Bloc, TitreDeSection, Tuile, Balise, ChoixSegmente). Une brique nouvelle d'envoi de fichier (`shared/lib/envoi.ts`) et la carte MapLibre (pour les cercles des cultures). Les écritures des énigmes passent par des fonctions serveur nouvelles (mig 519) ; les tables qui ont déjà une politique d'écriture réservée aux admins (natures, titres, bannières, réglages) s'écrivent directement (décision R1).

**Tech Stack:** celle des plans 1-2 + `maplibre-gl` 6.11.2 (même version que `apps/web-v2`).

**Spec:** `docs/superpowers/specs/2026-10-14-hub-v2-design.md` (§4, §6, §11 : modèles « liste + fiche en tiroir » pour Énigmes, Cultures, Natures, Titres, Bannières ; « file à deux volets » pour Énigmes signalées ; « réglages » pour Énergie).

## Global Constraints

- Tout ce que disent les plans 1 et 2 (Global Constraints) vaut ici ; en particulier : worktree **hors du dépôt** avec la casse exacte du chemin ; TS strict ; jetons seulement ; en-têtes QUOI/POURQUOI ; README par dossier ; composant → hook → api ; tout état navigable est une URL (filtres, page, élément ouvert) ; animations par les jetons ; `prefers-reduced-motion` ; pas de `console.log` ; Conventional Commits + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Le tiroir garde l'état de la liste** : un lien de ligne va vers `{ pathname: id, search: location.search }` ; le `retour` du tiroir est `LISTE + location.search` (règle prise au plan 2).
- Migration **519** (une seule). Les écritures en production sont soumises à l'accord d'Uriel (le contrôle automatique les refuse depuis le 14/10) : écrire, tester en lecture seule, **ne pas appliquer** ; le contrôleur la fait appliquer avec la 518.
- Fonctions du Hub : `SECURITY DEFINER`, `SET search_path TO 'public'`, `IF NOT _is_admin() THEN PERFORM _refus('Réservé à l’équipe', 'role'); END IF;` en premier, `REVOKE ALL … FROM PUBLIC, anon; GRANT EXECUTE … TO authenticated;`.
- **R1 — écritures directes permises** seulement là où une politique RLS d'écriture réservée aux admins existe déjà (vérifiée le 14/10) : `tags` (insert/update/delete admin), `titles` (`equipe_ecrit`, `_is_admin()`), `home_banners` (« admin manage »), `app_settings` (`app_settings_admin_write`), et les buckets `tag-icons`, `home-banners` (écriture `_is_admin()`). Partout ailleurs, une fonction serveur.
- Une suppression n'existe que là où l'ancien Hub l'offrait **et** sans casser l'historique : **une énigme ne se supprime pas, elle se désactive** (les réponses des joueurs la référencent) ; une bannière se supprime (avec son fichier) ; un titre de chemin se supprime ; une nature ne se supprime pas (elle a des lieux).
- Vocabulaire : « culture » à l'écran (table `enigma_themes`), « nature » (table `tags`), « titre », « énigme », « percer ».
- Un enregistrement réussi rafraîchit la fiche et la liste (TanStack Query) ; une erreur s'affiche sous son bloc avec le message de la base ; un champ modifié efface « Enregistré. ».

## Review Focus

1. **Une énigme QCM dont la réponse ne figure pas parmi les choix** → refusée avant d'envoyer, et par la base si on contourne (« La réponse doit être l’un des choix »). (Test : Task 2 et SQL Task 1.)
2. **Un titre de connaissance ouvert dans l'éditeur** → sa condition (`theme`, `palier`) ne peut pas être remplacée par un autre chemin ; seuls nom, nom au féminin, description et icône se modifient. (Test : Task 6.)
3. **Une valeur d'Énergie qui casserait la règle** (paliers non croissants, prix décroissants, moins de 10 minutes par point) → refusée avant d'écrire, rien n'est écrit. (Test : Task 8.)
4. **Un fichier trop lourd ou d'un type refusé** (bannière : jpeg/png/webp ≤ 5 Mo ; icône de nature : svg ; icône de culture : svg/png/webp) → message clair avant l'envoi, aucun fichier orphelin. (Test : Task 3 `envoi`.)
5. **Une culture dont on retire tous les cercles** → la base refuse (elle ne s'éveillerait plus nulle part) ou le Hub prévient avant d'enregistrer. (Test : Task 5.)
